# Judges FAQ

## Q1: 你们的贝叶斯更新严格吗？

不是严格生产级贝叶斯推断。

我们使用“贝叶斯风格”的可解释信念更新，将候选人信号、HR 行为、报价变化转化为信任、底线强度、外部选择和入职确定性等可观察指标。目标是训练用户理解“信息如何改变对方判断”，而不是声称统计上验证过真实招聘市场。

可以这样表述：

> 这是一个规则优先的决策教练原型，贝叶斯模块用于解释信念变化，不是生产级统计估计器。

## Q2: LLM 幻觉怎么办？

系统采用规则优先架构。

核心报价、耐心变化、筹码影响、结果页 What-if、demo fallback 都有确定性规则路径。LLM 主要用于文本表达、解析和复盘增强。

如果 LLM 不可用或输出质量不稳定：

1. 规则引擎仍可跑通主流程。
2. 前端仍有 25 场 seeded negotiation histories。
3. 结果页 memo、strategy tree、What-if 仍可演示。

可以这样表述：

> LLM 是表达层增强，不是唯一决策源。我们把关键状态留在规则系统里，降低幻觉风险。

## Q3: What-if 是不是重新跑了一遍博弈？

第一版不是完整重跑均衡，而是前端近似推演。

它根据报价变化、策略姿态、市场热度和 HR 耐心，估计成交概率、最终薪资、破裂风险和信任变化。UI 中明确标注“近似推演”。

可以这样表述：

> What-if 的价值是训练决策直觉，让用户理解“多要 5K”可能带来的收益和风险，不把它包装成严格重算。

## Q4: 筹码卡是不是鼓励造假？

不是。

UI 已经将旧的信息战语义改成：

- 强调：突出真实且可验证的优势。
- 重组：换一个更有利的叙事角度表达真实经历。
- 弱化：降低不利信息显著性，但会带来信誉影响。

系统还加入本地信誉分：高可信筹码可提升信誉，风险较高的重组会降低信誉。

可以这样表述：

> 我们训练的是如何组织真实经历，而不是虚构经历。信誉机制反而抑制了过度包装。

## Q5: 为什么不接真实招聘网站数据？

当前阶段优先保证合规、稳定和可解释。

真实招聘网站数据涉及授权、反爬、质量、更新频率和偏差问题。我们没有把未经授权的爬取作为核心能力。

当前项目使用：

- 中国互联网职场规则。
- 公司/职级/技能/稳定性等本地模型。
- 25 场覆盖多岗位和多结果的 demo histories。

后续可接入授权数据源或手动维护薪资带宽知识表。

## Q6: 这个系统和普通 LLM 聊天有什么区别？

普通 LLM 往往给泛泛建议。本系统维护结构化状态：

- HR 耐心。
- HR 信任。
- 外部选择强度。
- 候选人底线强度。
- 筹码信誉。
- 报价轨迹。
- 策略树。
- What-if 数值推演。

LLM 只增强文本表达，规则系统负责状态与边界。

## Q7: 如果评委只给 3 分钟，应该演示什么？

只演示一个闭环：

1. 首页定位：薪资谈判教练。
2. Play setup：Coach Mode 已开启。
3. 谈判中：CoachPanel 给出下一步建议和 HR 画像。
4. 筹码卡：强调/重组/弱化真实经历，展示信誉变化。
5. 结果页：谈判备忘录、策略树、What-if。

不要在短时间里同时展开 debate、analysis、simulation、dashboard 全部页面。

## Q8: 项目的最大创新点是什么？

不是单一模型，而是把谈薪中的隐性判断显性化：

- HR 如何看我。
- 我应该如何组织筹码。
- 当前报价会如何影响信任和破裂风险。
- 如果换一种报价路径，结果可能如何变化。

可以这样收束：

> 我们不是让 AI 替用户谈薪，而是把谈薪中的隐性判断显性化，让用户下次真实面试能更会谈。
